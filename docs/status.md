- Current focus: **Checkpoint 14 — App Server and Alternate Surfaces**, with `14d` ready for learning discussion.
- Next checkpoint: **14e — WebSocket transport**.
- Latest committed sub-step: **14d — TUI clear-key polish**.
- Planned next order: discuss 14d learnings, then add WebSocket as another transport for the same App Server protocol.
- Current user-visible behavior: one user prompt can trigger repeated `read_file`, `list_files`, approval-gated or mode-gated `write_file`, approval-gated or mode-gated `edit_file`, approval-gated or mode-gated `shell`, configured MCP tools, configured plugin command-backed tools, and plan-mode `exit_plan_mode` calls. Before each model request, cawir assembles a provider-neutral system prompt from named identity, behavior, environment, project-guidance, and active-skill sections; project guidance is loaded from `AGENTS.md` / `CLAUDE.md` files found through the project hierarchy, skill metadata is discovered from cawir skill manifests, skill instruction bodies are not deserialized, validated, stored, or inserted into the prompt until the current user prompt matches a skill, and tool schemas remain in provider-native structured tool fields instead of prompt text. Anthropic serializes that prompt as a system text block with an explicit `cache_control` breakpoint while also sending top-level automatic `cache_control`, so stable tools/system/project guidance and the growing conversation can cache independently. Runtime owns the `ToolRegistry`, populated from built-ins plus stdio MCP servers configured in cawir settings under `mcp_servers` or `mcpServers` plus plugin tools from configured plugin directories, a `HookRegistry` populated from cawir-owned user/project/local settings plus plugin hook contributions, and a `SkillCatalog` populated with metadata and manifest paths from cawir settings under `skills.directories` / `skill_dirs` plus plugin `skills/` folders; MCP tools are registered as namespaced tools such as `mcp__server_name__tool_name`, plugin tools are registered as `plugin__plugin_name__tool_name`, and both execute through the same pre/post hook, event, permission, and tool-result path as built-ins. Configured command hooks receive event JSON on stdin and can allow, deny, or modify pre-tool input before tool execution, while post-tool hooks can observe completed tool events. Provider responses carry provider-neutral metadata, and the REPL prints available per-request token usage including Anthropic cache creation/read token counts, the exact advertised tool-definition fingerprint, and active skill names when any skills are selected. HTTP 429 responses are returned as typed rate-limit errors with parsed `retry-after` seconds when providers send that header. cawir streams Anthropic SSE, OpenAI chat-completions SSE, and OpenAI Codex Responses SSE into provider-neutral text and tool-use delta events; the agent maps those into serializable `AgentEvent` values, the REPL renders assistant text as it arrives without duplicating the final message, and tool calls still execute through the normal tool-result loop after the streamed response completes. Ollama remains non-streaming for now. cawir sends matching `tool_result` blocks back to the active provider and continues until the provider returns a text answer, the 42-round tool-loop cap is reached, or plan mode asks the REPL for plan approval. Agent lifecycle and progress are emitted as serializable typed `AgentEvent` values, including session start/end, model request start/finish with metadata, tool fingerprint, and active skill names, pre/post tool-use events, assistant text/tool-use stream deltas, normal stops, and structured stop failures; `PostToolUse` includes the original tool input for hook consumers, while `tool_result` blocks remain session data sent back to providers, not display events. In plan mode, either an `exit_plan_mode` call or a plain text final answer is treated as a proposed plan. Tool execution failures, denied mutating actions, MCP tool errors, MCP protocol errors, plugin command-tool errors, hook denials, denied tool-backed plans, output truncation notices, and shell timeouts are returned inside tool results instead of aborting the turn. `edit_file` changes existing UTF-8 files by exact `old_string` → `new_string` replacement, requires a unique match unless `replace_all` is true, and leaves `write_file` for new files and full rewrites. `read_file` returns at most 64 KiB by default and marks truncated UTF-8-safe prefixes; `list_files` returns at most 200 directory entries before a truncation marker; `shell` caps stdout and stderr separately at 32 KiB and times out after 30 seconds. Startup honors `CAWIR_PROVIDER`, otherwise reuses the saved provider, credential option, and per-provider-plus-auth-option model choices from the OS config directory, then scans providers for usable credentials; if none are configured, startup prompts for a provider before credential setup. Startup prints the selected provider, auth option, credential source, model, session id, and active permission mode. Non-empty conversations are saved as session JSON in the OS data directory after slash-command state changes, exits, and turns; brand-new empty sessions are not written to disk. Sessions store the canonical project path and last advertised tool-definition fingerprint; `cawir --continue` opens the most recently updated non-empty session for the current project, while `cawir --resume <id>` opens a specific session by id. Resumed sessions print the previous conversation, with tool calls and tool results summarized, and warn when the current tool-definition fingerprint differs from the saved fingerprint because the next provider request may rebuild prompt cache. Slash commands are dispatched through a built-in-plus-plugin `CommandRegistry`: bare `/provider` lists provider options; `/provider anthropic|openai|ollama` switches providers inside the REPL after resolving or acquiring a supported credential option from the credentials file, environment, `.env`, API-key prompt, Codex OAuth device-code login, or local no-auth setup, and warns that existing history will be sent to the new provider. Bare `/resume` lists non-empty saved sessions for the current project newest-first, excluding the currently active session; `/resume <id>` switches the running REPL to a saved session, reloads that project's commands, hooks, skills, MCP tools, and plugin tools, and prints its transcript. `/model` shows the current model, the active provider/auth default, and dynamically queried available models where the provider exposes a model-list endpoint; `/model <name>` switches the model for the current provider/auth route and remembers it. `/mode` shows the current permission mode; `/mode default|plan|accept-edits|bypass` switches the current permission mode for the running REPL. OpenAI API-key auth still uses the OpenAI chat-completions endpoint; OpenAI Codex OAuth uses the ChatGPT Codex backend Responses route. Ollama uses the local `http://localhost:11434/api/chat` endpoint with native Ollama tool calls and defaults to `qwen3:8b`.

## In-progress checkpoint notes

### 14 — App Server and Alternate Surfaces

- `14a` and `14b` completed in implementation commit `9421c42` after commit `b149693` reframed the checkpoint around an App Server foundation. `src/app_server.rs` adds stdio JSONL framing, JSON-RPC-style request/response/notification envelopes, `initialize`, `shutdown`, `session/new`, `session/resume`, and `turn/submit` against a single active session. `src/runtime.rs` extracts provider dispatch, runtime handles, project tool/skill loading, session syncing/saving, tool-fingerprint resume warnings, and generic turn execution below surfaces. `repl.rs` keeps terminal rendering, slash commands, credential setup prompts, and approval prompts, but now calls `runtime::run_agent_until_complete` with surface-specific tool and plan approval callbacks. `app-server` emits `AgentEvent` values as `event` notifications and asks clients for `approval/tool` or `approval/plan` decisions as server-initiated protocol requests. App Server startup is intentionally non-interactive: it uses already-configured credentials or returns structured protocol errors so stdout remains JSONL-only. Evidence: `cargo fmt --check`, `cargo test`, `cargo clippy --all-targets -- -D warnings`, `git diff --check`, and a manual `cargo run --quiet -- app-server` initialize/session-new/shutdown JSONL smoke test passed. Learning notes saved in `learnings-agent/11-agent-events-and-surfaces.md`, `learnings-rust/35-fnmut-event-callbacks.md`, and `learnings-rust/41-serde-tagged-event-enums.md`.
- `14c` completed on 2026-05-27 in implementation commit `fd46697`. The implementation adds `src/exec.rs` and wires `cawir exec "..."` into `src/cli.rs` as the first real App Server client. `exec` starts `cawir app-server` as a child process, sends `initialize`, `session/new` or `session/resume`, `turn/submit`, and `shutdown` JSONL requests, renders assistant text in human mode, emits structured JSONL in `--json` mode, and answers `approval/tool` or `approval/plan` server requests with a conservative deny-by-default policy unless `--approve` is passed. It supports `--provider`, `--model`, and `--resume` for one-shot session setup. Evidence: `cargo fmt --check`, `cargo test`, `cargo clippy --all-targets -- -D warnings`, `git diff --check`, `cargo run --quiet -- exec --help`, an expected-error smoke test `cargo run --quiet -- exec --provider definitely-not-a-provider "hello"` passed through the real `exec` -> child `app-server` protocol path, and the user successfully ran `cargo run -- exec "reply with exactly: ok"` against saved OpenAI Codex OAuth config. Learning notes saved in `learnings-agent/11-agent-events-and-surfaces.md` and `learnings-rust/47-child-process-stdio-clients.md`.
- `14d` completed on 2026-05-27 in implementation commit `2d2e376`. The implementation adds `cawir tui`, `src/tui.rs`, and shared `src/app_client.rs` protocol helpers used by both `exec` and TUI. The TUI starts `cawir app-server` as a child process, initializes or resumes a session, then renders a Ratatui/Crossterm MVP with transcript, status, tool timeline, approval, and input panes. A background thread reads App Server JSONL messages into the UI loop through a channel so streaming events and approval requests can update the screen without blocking keyboard handling. Approvals are interactive in the TUI: `a` approves, `d` or `Esc` denies; `Enter` submits input; `q` or Ctrl-C quits; `/exit` and `/quit` exit locally without sending a model turn. The input pane tracks its own cursor, renders the terminal cursor inside the box, and supports left/right, home/end, backspace, and delete editing inside the line instead of only appending at the end. Evidence: `cargo fmt --check`, `cargo test`, `cargo clippy --all-targets -- -D warnings`, `git diff --check`, `cargo run --quiet -- tui --help`, an expected-error smoke test `cargo run --quiet -- tui --provider definitely-not-a-provider` passed through the real `tui` -> child `app-server` setup path, focused TUI tests cover local slash-exit, cursor-aware editing, and rendered cursor placement, and PTY smokes launched `cargo run --quiet -- tui --provider ollama --model qwen3:8b` then exited with `q` and `/exit` without making a model request. Learning notes saved in `learnings-agent/11-agent-events-and-surfaces.md` and `learnings-rust/48-ratatui-crossterm-event-loops.md`.
- `14d` input polish completed on 2026-05-27 in implementation commit `61932b8`. It replaces the TUI's hand-rolled input string and byte cursor with `ratatui_textarea::TextArea`, using the crate's backend-neutral `Input` type so readline-style shortcuts such as `Ctrl-A`, `Ctrl-E`, and `Alt-B` work without implementing local line-editing rules. cawir still renders the single-line input pane itself and places the terminal cursor explicitly, because `ratatui-textarea 0.9` uses Ratatui's newer split crates while this TUI still renders through monolithic `ratatui = 0.29`. Evidence: `cargo fmt --check`, `cargo test`, `cargo clippy --all-targets -- -D warnings`, `git diff --check`, and focused TUI tests cover arrow editing, local slash-exit, rendered cursor placement, `Ctrl-A`/`Ctrl-E`, and `Alt-B`.
- `14d` clear-key polish completed on 2026-05-27 in implementation commit `7f03e8b`. It makes Ctrl-C and Esc clear the TUI input buffer instead of quitting the program or denying a pending approval. Clear-input keys are handled before approval keys and before textarea editing keys, so `d` remains the explicit deny key for pending approvals. Evidence: `cargo fmt --check`, `cargo test`, `cargo clippy --all-targets -- -D warnings`, `git diff --check`, and focused TUI tests cover Ctrl-C not being a quit key, Ctrl-C clearing without submitting, and Esc clearing without denying approval.
